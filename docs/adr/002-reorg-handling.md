# ADR-002 reorg와 입금 확정

상태: 선택(B)은 출처: 사람 설계 · 감지 방법·확정 정책·세부 규칙은 확정: 오케스트레이터 · 지키는 불변조건: I4, I1, I2, I3

## 맥락

체인에서 본 입금 tx는 그 블록이 canonical chain에서 빠지면 없던 일이 된다(reorg). 빠진 tx가 다른 블록에 다시 들어갈 수도, 영영 안 들어갈 수도 있다. 입금을 언제 원장에 기록하고 언제 사용자가 쓸 수 있게 하느냐가 I1(없는 돈을 쓰게 하지 않음)과 I4(확정은 canonical chain과 정책으로만)를 정한다.

## 대안

| 안 | 내용 | 판단 |
| --- | --- | --- |
| A. 확정 뒤에만 기록 | 확정 수 N에 이르기 전에는 원장에 아무것도 쓰지 않고, 이르면 사용자 계정에 한 번 기록 | 확정 전 입금이 원장에 없어 "보였지만 아직 아님"을 대사·조회할 수 없다. reorg 감지는 어차피 필요하다 |
| **B. 잠정 입금 계정에 기록, reorg 시 역분개** | 보이자마자 `pending_deposit`에 기록(사용자는 못 씀). N에 이르면 `user`로 옮기고, 그 전에 블록이 빠지면 역분개 | **고름(출처: 사람 설계)**. 확정 전 상태도 원장에 남고, reorg의 흔적이 역분개로 남는다 |
| C. 즉시 사용자 잔액, reorg 시 회수 | 보이자마자 `user`에 기록하고 빠지면 회수 | 그 사이 사용자가 출금하면 회수할 수 없다. I1 위반 |

## 결정

1. **확정 정책.** 확정 수 = (처리한 canonical head의 번호) − (입금 블록 번호) + 1. 확정 수가 N 이상이고 그 블록이 저장된 canonical 헤더에 있을 때만 확정한다. N은 설정값이고 테스트는 작은 값(예: 3)을 쓴다. 정책은 "N보다 깊은 reorg는 일어나지 않는다"는 가정이다.
2. **끌어오기(pull)로 순서대로 처리.** 스캐너는 커서(마지막으로 처리한 canonical 블록의 번호·해시) 다음 번호의 블록을 체인에 요청한다. 새 head 알림은 몇 번이 어떤 순서로 오든 "스캔하라"는 신호일 뿐이다. 처리 순서는 (블록 번호, tx 위치)로만 정해진다(F8).
3. **블록 하나 처리 = DB 트랜잭션 하나.** 부모 해시가 커서 해시와 같으면, 한 트랜잭션에서: 블록 헤더(번호·해시·부모 해시) 저장 → 우리 입금 주소로 온 성공 tx마다 잠정 입금 분개 → 확정 수가 N에 이른 잠정 입금의 확정 분개 → 커서 전진([ADR-001](001-ledger-model.md) 결정 8, I5).
4. **reorg 감지.** 받은 블록의 부모 해시가 커서 해시와 다르면 reorg다. 블록 번호만 보고 넘어가지 않는다.
5. **되감기.** 커서에서 아래로 내려가며 체인의 그 번호 블록 해시와 저장된 해시를 비교해, 처음 같아지는 곳을 공통 조상으로 잡는다. 한 트랜잭션에서: 공통 조상보다 위의 저장 헤더를 고아로 표시 → 그 블록들의 확정 전 잠정 입금마다 역분개(키 `dep:revert:…:{block_hash}`) → 커서를 공통 조상으로 옮김. 그다음 평소처럼 새 분기를 앞으로 처리한다.
6. **다시 들어간 tx.** 빠진 tx가 새 분기의 블록에 다시 들어가면 블록 해시가 달라 새 잠정 입금 키가 생긴다. 확정 키에는 블록 해시가 없어 tx 하나는 최대 한 번만 확정된다(I2).
7. **확정 뒤 깊이의 reorg.** 고아가 될 블록에 이미 확정된 입금이 있으면 정책 가정이 깨진 것이다. 원장은 바꾸지 않고(확정된 입금은 되돌리지 않는다), 사고 기록(`finality_violations`: 블록·tx·금액)을 남기고 입금 처리를 멈춘다. 다시 시작은 사람이 판단한다. 자동으로 사용자 잔액을 빼면 이미 출금된 돈 때문에 음수가 되거나, 맞지 않는 회수가 생긴다.
8. **공통 조상을 못 찾으면.** 저장된 헤더 범위를 넘는 깊이면 7과 같이 멈춘다.
9. **조회 실패는 블록 없음이 아니다.** 블록 조회가 `Indeterminate`(타임아웃 등)이면 커서를 움직이지 않고 다시 시도한다. 빈 블록이나 reorg로 해석하지 않는다(I6). 요청한 번호가 아직 head보다 위면 기다린다.

## 검증

[SYSTEM_INVARIANTS](../SYSTEM_INVARIANTS.md#증명-테스트)의 T1.2, T2.3, T3.3, T4.1–T4.5, T6.5(모두 03-deposit-reorg). 가짜 체인(`vault-sim`)이 분기 만들기·바꾸기, 같은 블록 재전달, 알림 섞기, 조회 타임아웃을 주입한다.

## 바꿀 신호

| 신호 | 바꿀 것 |
| --- | --- |
| 대상 체인이 finality 표시(EVM의 `finalized` 블록 태그)를 믿을 만하게 준다 | 확정 정책을 "확정 수 N" 대신 "finalized 블록 이하"로 바꾸는 정책 구현을 더한다. 정책은 trait 하나로 둔다 |
| `finality_violations`가 실제로 기록된다 | N을 키우고, 확정 뒤 회수 절차(사람 승인 분개)를 설계한다 |
| 블록마다 전체 tx를 받는 비용이 커진다 | 입금 주소 필터 조회(로그·trace 인덱서)로 바꾸되, 블록 해시 연결 검사는 그대로 둔다 |
| ERC-20 입금이 생긴다 | tx 대신 로그(`Transfer`)를 입금 단위로 하고 키에 로그 위치를 더한다 |
